# 草台编子识字班 · 论坛互动 v0.4 实现规格

本规格描述 v0.4 的论坛互动能力：活跃排序、课程讨论帖在论坛里的展示、关注帖子、回复点赞、每日摘要邮件和 MCP 关注 / 点赞工具。课程反馈本体见 [课程反馈 v0.4 实现规格](草台编子识字班课程反馈v0.4实现规格.md)。

## 1. 范围

做：

- 论坛列表升级为活跃排序。
- 课程讨论帖在论坛列表中可见，有新回复时按普通帖子活跃，并带专门标签或样式。
- 用户可以关注帖子；自己发的帖子默认关注，也可以取消关注自己的帖子。
- 用户在课程页提交反馈后，自动关注对应课程讨论帖。
- 用户手动回复任意论坛帖时，自动关注该帖子。
- 用户中心提供“关注的帖子”入口。
- 回复点赞，作为课程页高赞回复和每日摘要点赞数据来源。
- 每日邮件摘要默认开启，汇总关注帖子新回复和关注帖子中“我的回复”收到的点赞。
- MCP 支持关注 / 取消关注帖子、点赞 / 取消点赞回复。

不做：

- 帖子点赞。
- 即时逐条通知。
- 管理员手动触发每日摘要群发入口。
- 主动通知管理员每日摘要失败。
- 关注分组、收藏夹、复杂通知中心。

## 2. 论坛活跃排序

`forum_posts` 新增：

```sql
last_activity_at
```

规则：

- 创建帖子时 `last_activity_at = created_at`。
- 新增公开回复时刷新帖子 `last_activity_at`。
- 课程反馈同步为公开回复时，也刷新课程讨论帖 `last_activity_at`。
- 隐藏 / 删除回复不倒退 `last_activity_at`。
- 论坛列表排序：置顶优先，再按 `last_activity_at` 倒序。
- 既有帖子迁移时，`last_activity_at` 初始取 `created_at`，或按已有公开回复最大时间回填。

课程讨论帖：

- 显示在论坛列表中。
- 不默认置顶。
- 有新回复时按普通帖子活跃。
- 必须带固定标签或专门样式，例如“课程讨论”，不能伪装成普通学员帖子。

## 3. 回复点赞

新增回复点赞表：

```sql
forum_comment_votes
- comment_id
- user_id
- value                 -- v0.4 只支持 1
- created_at
```

规则：

- `unique(comment_id, user_id)`。
- 网页 UI 是 toggle：未点赞时点一下写入，已点赞时再点取消。
- 每个用户每条回复最多一个赞。
- 用户不能给自己的回复点赞，管理员也不例外。
- 隐藏 / 删除的回复保留既有点赞数据，但不计入课程页展示、论坛可见点赞数或每日摘要；恢复回复后点赞可恢复展示。
- 点赞操作单独限流，例如每用户每分钟最多 60 次。

课程页高赞回复：

- 展示赞数最高的 5 条回复。
- 赞数相同则展示最近的回复。
- 想看更多时，引导进入论坛完整讨论帖。
- 排除 hidden / deleted 回复。
- 不重复展示当前用户自己的同一条课程反馈同步回复。

## 4. 关注帖子

新增帖子关注表：

```sql
forum_post_subscriptions
- post_id
- user_id
- muted_at              -- 取消关注时填入；重新关注时置空
- created_at
- updated_at
```

规则：

- `unique(post_id, user_id)`。
- 用户创建帖子时默认写入关注记录。
- 用户在课程页提交反馈后，只要能确定课程讨论帖 `forum_post_id`，且用户此前没有取消关注该帖，就自动关注该讨论帖。
- 用户首次回复帖子时默认写入关注记录。
- 如果用户此前已取消关注某帖，后续回复不自动恢复关注，必须手动点击关注按钮。
- 用户可以取消关注自己发的帖子。
- 用户取消关注后，该帖的新回复和该帖内自己的回复点赞都不再进入每日摘要；即使用户是帖子作者也不例外。

用户中心：

- 提供“关注的帖子”入口。
- 普通用户只看到仍为 `published` 且自己有权限查看的关注帖子。
- hidden / deleted 帖子不显示给普通用户，但关注关系保留；帖子恢复后重新出现。
- 管理员可以在管理视图看到 hidden / deleted 的关注帖子用于排查。
- 用户可以取消关注或重新关注帖子。

## 5. 每日摘要

新增每日摘要偏好与发送记录：

```sql
notification_preferences
- user_id
- daily_digest_enabled  -- 默认 true
- unsubscribed_at
- updated_at

daily_digest_deliveries
- id
- user_id
- window_start
- window_end
- status                -- pending | sent | failed | skipped
- sent_at
- error_code
- created_at
- updated_at
```

规则：

- 每日邮件摘要默认开启。
- 退订只关闭每日摘要，不取消任何帖子关注。
- 单帖关注在用户中心管理。
- 每日摘要只从用户仍在关注的帖子里汇总动态。
- hidden / deleted 帖子不进入普通用户每日摘要。
- 新回复按关注帖子统计，但不计入用户自己的回复。
- 课程反馈同步出的论坛回复也算新回复，会进入该课程讨论帖关注者的每日摘要，但不通知回复作者本人。
- 点赞只统计这些关注帖中“我的回复”收到的点赞，不汇总关注帖内别人的点赞。
- 新回复摘要窗口按 `forum_comments.created_at` 计算；编辑旧回复不触发新摘要。
- 点赞摘要窗口按 `forum_comment_votes.created_at` 计算。
- 用户取消关注某帖后，该帖中自己的回复被点赞也不再进入摘要。
- 无新动态不发。
- 每日摘要只发给 `emailVerified = true` 的用户。
- 每日摘要任务必须显式跳过 `SYSTEM_USER_ID`。
- 发送时实时检查用户仍有论坛能力（v0.4 由 `course:full` 覆盖）；失去权限则不发，但保留关注关系。
- 同一 `user_id + window_start + window_end` 只能发送一次。
- 摘要发送记录只存元数据，不存邮件正文快照。
- 发送失败只记录 `daily_digest_deliveries.status = failed` 和 `error_code` 等元数据，v0.4 不主动通知管理员。

发送窗口：

- 使用站点统一时区 `Asia/Shanghai`。
- 汇总上一自然日 `00:00:00-23:59:59`。
- 次日 09:00 左右发送。
- 由 Cloudflare Cron Trigger 触发，Wrangler cron 使用 UTC 时间配置，北京时间 09:00 对应 UTC 01:00。
- 发送任务失败可在当天重试，但同一用户同一汇总窗口不得重复发送。

邮件内容：

- 包含非常短的内容摘要，但不包含完整 Markdown。
- 每个帖子展示标题、新回复数量、最多 2 条 80 字以内回复摘要和论坛链接。
- 点赞部分展示回复短摘要和点赞数。
- 摘要中可以出现论坛帖子标题和课程讨论帖标题中的课程标题，但不得包含课程正文。
- 邮件底部必须有退订链接或关闭说明。
- 退订链接免登录生效，但必须使用服务器签名 token，不能只靠 userId 或邮箱。
- 退订 token 至少包含 user id、用途和过期时间或版本；点击后只关闭每日摘要，不取消关注关系。
- 用户中心提供“每日摘要邮件”开关；邮件退订关闭后，用户登录后可以重新开启。
- 重新开启每日摘要不恢复任何已取消关注的帖子，只对当前仍关注的帖子生效。
- 用户关闭每日摘要后，新关注帖子、回复帖子或提交课程反馈都不能自动重新开启每日摘要；只能由用户在用户中心手动开启。

## 6. MCP 工具

MCP 在 v0.4.0 支持关注帖子和回复点赞，但必须复用网页同一服务层、权限检查和限流。

Scope：

- 关注 / 取消关注帖子要求 `mcp:write`。
- 点赞 / 取消点赞回复要求 `mcp:write`。
- 每次调用实时检查用户仍有 `course:full`。

工具名使用现有下划线风格：

- `forum_post_follow`
- `forum_post_unfollow`
- `forum_comment_like`
- `forum_comment_unlike`

网页 UI 可以做 toggle；MCP 工具使用显式 like / unlike、follow / unfollow，避免 Agent 误切状态。点赞和关注工具不提供 dry run。

## 7. 执行节奏

按 [agents/collaboration.md](agents/collaboration.md) 的前后端分轮：

0.4.0 总实现顺序：

1. 先做论坛互动基础：`last_activity_at`、关注帖子、回复点赞、个人中心“关注的帖子”。
2. 再做课程反馈：`course_feedback`、课程讨论帖、课程页反馈区、后台统计、MCP 反馈工具。
3. 最后做每日摘要：在关注、点赞、回复数据稳定后，再接 Cloudflare Cron Trigger + DirectMail。

**第 1 轮 · 前端契约与 UI**

- 帖子详情页补关注按钮和回复点赞按钮。
- 用户中心补“关注的帖子”。
- 课程页高赞回复展示对接点赞数据。
- 每日摘要偏好开关入口。

**第 2 轮 · 后端实现**

- 新增 D1 migration 和 Drizzle schema：`forum_posts.last_activity_at`、`forum_comment_votes`、`forum_post_subscriptions`、`notification_preferences`、`daily_digest_deliveries`。
- 更新 `lib/forum.ts` 的列表排序和回复写入路径，使有新回复的帖子自然浮上来。
- 实现关注 / 取消关注。
- 实现回复点赞 / 取消点赞。
- 实现个人中心“关注的帖子”查询。
- 实现每日摘要任务：由 Cloudflare Cron Trigger 触发，按 `Asia/Shanghai` 上一自然日窗口汇总，调用 DirectMail 发送，并用 `daily_digest_deliveries` 保证幂等。

**第 3 轮 · MCP**

- 新增关注 / 取消关注、点赞 / 取消点赞 MCP 工具。
- 全部复用网页服务层。

## 8. 验收标准

- 论坛列表按置顶优先、`last_activity_at` 倒序排序。
- 普通帖子和课程讨论帖有新公开回复时都会自然浮上来。
- 课程讨论帖在论坛列表中有“课程讨论”标签或专门样式。
- 用户创建帖子后默认关注。
- 用户首次回复帖子后默认关注。
- 用户取消关注后，后续回复不自动恢复关注。
- 帖子作者取消关注自己的帖子后，不再收到该帖每日摘要。
- 用户不能给自己的回复点赞。
- 隐藏 / 删除回复的点赞不计入展示和每日摘要。
- 课程页展示赞数最高的 5 条回复，同赞数取最近。
- 每日摘要只发给 email verified、仍有论坛权限、开启摘要且有新动态的用户。
- 同一用户同一汇总窗口不重复发送。
- 退订每日摘要不取消帖子关注。
- MCP 关注 / 点赞工具与网页行为保持同语义。
- `pnpm typecheck` 和 `pnpm build` 通过。

## 9. MCP 验收 Checklist

用一个普通学员账号验收即可；每日摘要不需要管理员群发入口，验收重点是关注、点赞和摘要数据前置条件。

- `forum_read_post`：选择一个普通帖子和一个课程讨论帖。
- `forum_post_follow`：关注帖子，确认用户中心“关注的帖子”能看到。
- `forum_post_unfollow`：取消关注，确认用户中心不再显示；后续自己回复该帖不自动重新关注。
- 手动在网页或 MCP 回复一个从未关注过的帖子，确认首次回复会自动关注。
- `forum_comment_like`：点赞别人的回复，确认赞数增加。
- 再次调用 `forum_comment_like` 不应作为 toggle；MCP 应使用显式工具，已点赞时保持幂等或返回已点赞状态。
- `forum_comment_unlike`：取消点赞，确认赞数减少。
- 尝试点赞自己的回复，确认被拒绝。
- 关注一个帖子后，让另一个学员新增回复；确认该回复会进入下一次每日摘要候选。
- 取消关注该帖后，确认该帖新回复和该帖内自己的回复点赞都不再进入每日摘要候选。
- 关闭每日摘要后，再关注帖子或回复帖子，确认不会自动重新开启每日摘要。
