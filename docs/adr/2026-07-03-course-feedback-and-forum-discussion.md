# 课程反馈与论坛讨论分层

- 日期：2026-07-03
- 状态：已采纳（Accepted）

## Context

项目已经有登录、卡密 entitlement、课程正文读取和论坛 v1。现在真实学员开始使用课程，需要在每节课底部收集学习反馈：学员必须选择一个状态（顺利 / 内容难懂 / 操作卡住），并写下非空文字。与此同时，课程页也需要复用论坛讨论能力，让反馈和讨论不变成分散孤岛。

直接把课程反馈做成“论坛帖子 + 投票”会让后台统计变脏：论坛回复是公共讨论流，允许多次回复、跑题、被隐藏或删除；课程反馈则是每个学员对每节课的一条学习状态记录，需要唯一、可改、可聚合。

## Decision

课程反馈与论坛讨论分层：

- `course_feedback` 作为结构化统计真相：每个用户每节课一条，必须有状态和非空文字，服务端校验登录 + entitlement。
- 每节课关联一个由系统账号随课程文章生命周期自动维护的课程讨论帖；反馈文字提交后同步或引用为该讨论帖下的一条论坛回复。
- 课程页底部展示反馈表单、个人已提交反馈、整体状态汇总，以及课程讨论帖中的若干回复。
- 论坛继续负责公开讨论、回复可见性、作者/管理员权限和后续点赞排序；课程反馈统计不从论坛楼层反推。

## Consequences

- 管理员能得到稳定的课程维度统计，不会被论坛楼层生命周期污染。
- 学员仍能在论坛里看到完整上下文，课程页也能露出讨论现场。
- 实现上需要一个新的课程反馈服务层，并在它内部调用论坛服务层创建或更新关联回复；不能让课程页面直接绕过论坛规则写 `forum_comments`。
- 系统账号成为课程讨论帖生命周期的一部分，必须作为真实站点账号配置和排查，不能用第一个反馈学员冒充系统作者。
