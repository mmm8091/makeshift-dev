# 草台编子识字班 · 课程反馈 v0.4 实现规格

配套决策：[docs/adr/2026-07-03-course-feedback-and-forum-discussion.md](adr/2026-07-03-course-feedback-and-forum-discussion.md)。

本规格只描述课程反馈本体：反馈表单、课程讨论帖生命周期、反馈与论坛回复同步、课程页展示、后台统计和 MCP 反馈工具。论坛活跃排序、关注帖子、回复点赞、每日摘要邮件见 [论坛互动 v0.4 实现规格](草台编子识字班论坛互动v0.4实现规格.md)。

## 1. 范围

做：

- 每节课程底部显示反馈区。
- 学员必须选择一个状态，且必须填写非空文字，才能提交反馈。
- 状态三选一：
  - `smooth`：✅ 顺利
  - `confusing`：🤔 内容难懂
  - `blocked`：🐛 操作卡住
- 每个学员每节课只有一条课程反馈；再次提交是修改。
- 学员可以在课程页主动撤回自己的反馈。
- 反馈提交后，默认公开同步到该节课的课程讨论帖下，成为论坛回复。
- 课程页展示该节课反馈汇总和若干讨论回复。
- 管理员后台按课程查看反馈统计和反馈列表。
- MCP 支持读取反馈汇总、dry run、提交 / 更新 / 撤回课程反馈。

不做：

- 管理员精选回复。
- 复杂评分、星级、NPS。
- 匿名反馈。
- 私密反馈选项。
- 反馈状态历史或事件流。
- 未解锁用户反馈。
- 把课程反馈做成独立公开评论系统。

## 2. 产品形态

课程正文结束后显示一个“这一节学得怎么样？”区块。

未注册 / 未登录用户不显示课程反馈区；登录与解锁引导只在课程 Gate 里处理，课程底部不重复渲染反馈 Gate。课程正文是否公开与反馈区是否显示分开判断：公开课程也可以有内部反馈区，但只对登录且已解锁的学员显示。

表单包含：

- 状态单选，必选：`✅ 顺利` / `🤔 内容难懂` / `🐛 操作卡住`。
- 文字输入，必填，支持论坛同款 Markdown，上限 4000 字。
- 三种状态都必须填写非空文字；`✅ 顺利` 也不能只点状态不写内容。
- 明确提示：提交后会出现在本节课程讨论帖中，其他已解锁学员可见。
- 明确提示：不要粘贴 token、卡密、邮箱、手机号、私密路径、数据库内容或其他秘密。
- 明确提示：太长的问题适合单独发论坛帖，再把链接贴回来。
- 提交按钮。
- 已提交过时，显示当前状态和文字，按钮文案改为“更新反馈”。
- 已提交过时提供“撤回反馈”入口；撤回后从课程统计和课程页展示中移除。
- 更新反馈时允许只改状态或只改文字；最终保存后的状态必须存在，文字 trim 后必须非空。

文案引导：

- 顺利：写下这一节最有用的一句话、一个收获，或你准备怎么用。
- 内容难懂：指出哪一段、哪个概念没吃透。
- 操作卡住：写清楚卡在哪一步，能贴命令、报错、截图链接更好。

课程页不做大讨论流，只展示：

- 本节轻量反馈汇总：例如 `本节已有 20 条反馈：✅ 12｜🤔 5｜🐛 3`，只对已解锁用户展示。
- 当前学员自己的反馈。
- 关联课程讨论帖的若干回复。
- “查看全部讨论”链接到论坛帖子。

无反馈时不要只留空白，要显示求反馈的空状态设计，例如：

- “还没人反馈这一节，你可以当第一个探路的人。”
- 强调三种反馈都欢迎：顺利、难懂、卡住都对后续改课有用。
- 直接露出反馈表单，而不是只放一个跳转按钮。

同一条反馈回复在课程页不能重复展示：当前用户自己的反馈由“当前学员自己的反馈”区域承载，讨论回复列表不再重复展示这同一条同步回复；论坛完整讨论帖仍展示完整列表。

## 3. 数据模型

新增课程反馈表：

```sql
course_feedback
- id
- section_slug
- user_id
- status                -- smooth | confusing | blocked
- body_md               -- 非空，用户写的反馈文字
- forum_post_id         -- 关联课程讨论帖
- forum_comment_id      -- 同步生成或更新的论坛回复
- withdrawn_at          -- 反馈被隐藏 / 删除 / 撤回后填入，统计时排除
- created_at
- updated_at
```

约束：

- `unique(section_slug, user_id)`：每个学员每节课一条反馈。
- 反馈表示当前状态；更新时覆盖 `status` / `body_md` 并刷新 `updated_at`，v0.4 不保留完整历史。
- `withdrawn_at` 非空表示反馈已撤回；后台统计与课程页汇总只计算 `withdrawn_at IS NULL` 的反馈。
- `section_slug` 必须是已发布课程 slug。
- `status` 只能是三种闭集值。
- `body_md` trim 后不能为空。
- `forum_post_id` 指向课程讨论帖。
- `forum_comment_id` 指向该用户在课程讨论帖下由反馈同步出的回复。

新增课程讨论帖映射表：

```sql
course_discussion_threads
- section_slug
- forum_post_id
- created_by
- created_at
```

约束：

- `section_slug` 唯一。
- `forum_post_id` 唯一。
- 课程讨论帖由系统账号随课程文章创建自动创建，随课程文章删除自动软删除。
- 普通学员不能手动把任意帖子绑定到课程。
- 现有 `forum_posts.author_id` 是必填用户外键，系统账号必须是真实存在的站点账号；不能把第一个提交反馈的学员冒充为课程讨论帖作者。

## 4. 服务层

新增 `lib/course-feedback.ts`，作为课程反馈唯一服务层。UI、Server Action、MCP 或未来 API 都只跨这个接口，不直写表。

建议契约：

```ts
type FeedbackStatus = "smooth" | "confusing" | "blocked";

type CourseFeedbackSummary = {
  sectionSlug: string;
  counts: Record<FeedbackStatus, number>;
  total: number;
  viewerFeedback: CourseFeedbackView | null;
  discussionPostSlug: string | null;
  highlightedComments: CourseDiscussionComment[];
};

type CourseFeedbackInput = {
  sectionSlug: string;
  status: FeedbackStatus;
  bodyMd: string;
};

getCourseFeedbackSummary({ env, requestHeaders, sectionSlug }): Promise<CourseFeedbackSummary | null>
submitCourseFeedback({ env, requestHeaders, input }): Promise<WriteResult<{ feedbackId: string; discussionLinked: boolean }>>
withdrawCourseFeedback({ env, requestHeaders, sectionSlug }): Promise<WriteResult>
listCourseFeedbackForAdmin({ env, requestHeaders, sectionSlug?, status?, withdrawn?, cursor?, limit? }): Promise<AdminCourseFeedbackPage | null>
```

服务层职责：

- 校验 session。
- 校验用户拥有课程访问能力和论坛能力；v0.4 实际由 `course:full` 覆盖两者。
- 校验课程 slug 安全且课程已发布。
- 校验状态必选、文字非空。
- 校验反馈文字不超过 4000 字；前端计字和服务端校验共用 `FEEDBACK_BODY_MAX = 4000`。
- 校验反馈文字使用论坛同款 Markdown 安全规则：不开原始 HTML，链接协议白名单同论坛。
- 对提交 / 更新 / 撤回反馈做限流：每用户每课程每分钟最多 5 次，每用户每 10 分钟最多 30 次反馈操作。
- upsert `course_feedback`。
- 确保课程讨论帖存在。
- 调用 `lib/forum.ts` 的评论能力创建或更新对应论坛回复。
- 返回统计与当前学员个人反馈。

## 5. 课程讨论帖生命周期

- 课程文章创建或导入发布时，服务端同步创建课程讨论帖，作者为配置好的系统账号。
- `scripts/import-course-section.mjs` 在 upsert 课程时同步维护课程讨论帖：确保讨论帖存在，并在课程标题变化时同步讨论帖标题。
- 远程生产导入 published 课程时，如果系统账号不存在或讨论帖维护失败，导入脚本必须失败并退出非零，避免课程与讨论帖生命周期脱钩。
- v0.4 上线时提供一次性幂等补齐命令，例如 `pnpm course:discussions:backfill -- --remote`，扫描已发布课程补齐课程讨论帖，不触碰课程正文。
- 课程标题更新时，服务端同步更新课程讨论帖标题；课程标题是源头，讨论帖标题是派生物。
- 课程讨论帖正文使用固定系统引导，不引用课程标题、摘要、正文或其他课程内容。
- 课程 slug 改动视为迁移，必须保留既有反馈和讨论帖；迁移时同步更新 `course_feedback.section_slug` 与 `course_discussion_threads.section_slug`，`forum_post_id` 保持不变。
- 课程下架或删除时，服务端同步软删除课程讨论帖与映射，不物理删除学员讨论内容。
- 课程从 `published` 变为 `draft` 时，讨论帖标记为 `hidden`；课程硬删除或 slug 废弃时，讨论帖标记为 `deleted`。
- 系统账号使用真实存在的 admin profile，但只作为自动课程讨论帖作者；不得用于人类登录、Agent token、日常后台操作或其他业务身份。
- 系统账号通过环境变量 `SYSTEM_USER_ID` 指定；运行时必须校验该用户存在且 `profiles.role = admin`。系统显示名建议为“草台系统”，真实 user id / email 不写进仓库文档。
- 系统账号不接收每日摘要；每日摘要任务必须显式跳过 `SYSTEM_USER_ID`。
- 普通管理员仍可隐藏 / 恢复 / 删除课程讨论帖，但标题会随课程标题同步被覆盖，正文使用代码里的固定系统引导，不鼓励手改。
- 课程讨论帖被管理员删除后，映射进入异常状态；后台应提示缺失 / 已删除，并允许系统重建。
- 找不到课程讨论帖且无法创建时，反馈仍可保存；返回结果中标记 `discussionLinked: false`，后台提示管理员排查系统账号或映射。

课程讨论帖在论坛列表中的展示、活跃排序和专门标签 / 样式见 [论坛互动 v0.4 实现规格](草台编子识字班论坛互动v0.4实现规格.md)。

## 6. 论坛同步约束

- `course_feedback` 保存成功即视为反馈提交成功；论坛回复同步失败不得回滚反馈。
- 提交课程反馈时，只要能确定课程讨论帖 `forum_post_id`，且用户此前没有取消关注该帖，就自动关注该讨论帖；用户可之后在用户中心取消关注。关注规则见 [论坛互动 v0.4 实现规格](草台编子识字班论坛互动v0.4实现规格.md)。
- 反馈文字默认公开同步为论坛回复，状态标签随回复一起展示。
- 同步到 `forum_comments.body_md` 时，在正文第一行自动加状态标签，例如 `🐛 操作卡住`；用户原文从下一段开始。
- 用户更新反馈状态或文字时，论坛回复正文按当前 `status + body_md` 整体重写，旧状态标签不保留。
- 课程页允许修改状态和文字；论坛页只允许修改反馈文字，不允许在论坛页修改反馈状态。
- 论坛页编辑课程反馈同步出的回复时，必须识别 `course_feedback.forum_comment_id` 并转调 `lib/course-feedback.ts` 更新反馈文字，再由课程反馈服务层重写论坛回复；不能走普通 `editComment` 直接改 `forum_comments.body_md`。
- v0.4 不提供“仅管理员可见”的私密反馈模式；提交行为必须可预期。
- 反馈文字同步为论坛回复时，不绕过论坛权限、Markdown 安全、软删除和限流策略。
- 如果已有 `forum_comment_id`，再次提交反馈时必须更新同一条回复，而不是新增一层楼；该回复可显示已编辑或更新时间。
- 如果课程反馈同步出的论坛回复被管理员或作者隐藏 / 删除，对应 `course_feedback` 也标记为撤回，并从课程反馈统计中排除。
- 已撤回的反馈再次在课程页提交时，恢复同一条 `course_feedback`（清空 `withdrawn_at` 并更新状态 / 文字），但创建新的论坛回复，不复用已隐藏 / 删除的 `forum_comment_id`。
- 用户在课程页主动撤回反馈时，标记 `course_feedback.withdrawn_at`，并软删除或隐藏对应论坛回复。
- 如果论坛回复同步失败，保留 `forum_comment_id = null` 或旧值，并在后台暴露“未同步反馈”提示，供管理员后续补同步。

## 7. 权限

| 能力 | 要求 |
| --- | --- |
| 查看课程反馈区 | 登录 + 有效课程 entitlement + 有效论坛能力；v0.4 实际由 `course:full` 覆盖两者 |
| 提交 / 更新 / 撤回自己的反馈 | 登录 + 有效课程 entitlement + 有效论坛能力；v0.4 实际由 `course:full` 覆盖两者 |
| 查看本节统计 | 登录 + 有效课程 entitlement + 有效论坛能力；v0.4 实际由 `course:full` 覆盖两者 |
| 查看后台反馈列表 | `profiles.role = admin`，不要求 `course:full` |
| 查看课程讨论帖完整内容 | 登录 + 有效论坛能力 |

未登录或未解锁用户不能拿到课程反馈统计、反馈文字或讨论回复，也不在课程底部看到反馈区。

## 8. 后台统计

新增管理员页面：

```txt
/admin/course-feedback
/admin/course-feedback/[slug]
```

列表页展示：

- 课程标题、slug、order。
- 三种当前状态的计数和比例；统计只按 `withdrawn_at IS NULL` 的 `course_feedback.status` 当前值计算。
- 总反馈人数。
- 最近反馈时间。
- “操作卡住”数量优先提示。

详情页展示：

- 状态筛选。
- 撤回筛选：全部 / 有效 / 已撤回。
- 按时间倒序的反馈列表。
- 学员昵称、QQ 头像、状态、反馈文字、更新时间。
- 已撤回反馈的 `withdrawn_at`。
- 跳转到对应课程讨论帖。
- 未同步到课程讨论帖的反馈提示。

v0.4 不做复杂导出；如需人工复盘，可后续加 CSV。

## 9. 课程页展示策略

课程页底部展示回复时，排序优先级：

1. 展示赞数最高的 5 条回复。
2. 赞数相同则展示最近的回复。
3. 想看更多时，引导进入论坛完整讨论帖。

点赞数据与高赞回复查询见 [论坛互动 v0.4 实现规格](草台编子识字班论坛互动v0.4实现规格.md)。

课程页只展示少量回复，完整讨论仍在论坛帖中进行。反馈汇总不要做成排行榜、考试成绩或压力墙；学员端只需要轻量知道“有人顺利，也有人难懂或卡住”。

## 10. MCP 工具

MCP 在 v0.4.0 支持课程反馈，但必须复用网页同一服务层、权限检查和限流。

- MCP 提交课程反馈与网页完全同语义：默认公开同步课程讨论帖、自动关注、同样 4000 字限制、同样限流，并返回 `discussionLinked`。
- MCP 读取反馈汇总可用 `mcp:read`。
- 提交 / 更新 / 撤回课程反馈要求 `mcp:write`，并实时检查用户仍有 `course:full`。
- MCP 课程反馈提交提供 dry run 工具，用于检查 slug、权限、状态、字数、文字非空和公开同步提示。
- 工具名使用现有下划线风格：`course_feedback_get_summary`、`course_feedback_dry_run_submit`、`course_feedback_submit`、`course_feedback_withdraw`。

MCP 关注 / 取消关注帖子、点赞 / 取消点赞回复见 [论坛互动 v0.4 实现规格](草台编子识字班论坛互动v0.4实现规格.md)。

## 11. 执行节奏

按 [agents/collaboration.md](agents/collaboration.md) 的前后端分轮：

0.4.0 总实现顺序：

1. 先做论坛互动基础：`last_activity_at`、关注帖子、回复点赞、个人中心“关注的帖子”。
2. 再做课程反馈：`course_feedback`、课程讨论帖、课程页反馈区、后台统计、MCP 反馈工具。
3. 最后做每日摘要：在关注、点赞、回复数据稳定后，再接 Cloudflare Cron Trigger + DirectMail。

**第 1 轮 · 前端契约与 UI**

- 新建 `lib/course-feedback-types.ts`，冻结类型和字段。
- 课程页底部做反馈表单、个人反馈、状态汇总、讨论入口。
- 管理后台做统计列表和详情页 UI。
- 生产环境在后端门禁落地前，不暴露真实提交入口；可以用服务层 stub 验证交互。

**第 2 轮 · 后端实现**

- 新增 D1 migration 和 Drizzle schema：`course_feedback`、`course_discussion_threads`。
- 实现 `lib/course-feedback.ts`。
- 接入 Server Action。
- 配置系统账号，并在课程创建 / 下架 / 删除路径中维护课程讨论帖映射。
- 改造 `scripts/import-course-section.mjs`，让课程导入 / 更新时同步维护课程讨论帖。
- 新增课程讨论帖 backfill 脚本，扫描已发布课程补齐映射并同步标题，可重复运行。
- 在课程标题更新路径中同步更新讨论帖标题。
- 确保反馈回复同步复用 `lib/forum.ts`。
- 补后台查询和限流。

**第 3 轮 · MCP 反馈工具**

- 新增课程反馈 MCP 工具。
- 全部复用 `lib/course-feedback.ts` 的同一写入路径。

## 12. 0.4.0 还应顺手推进的事

课程反馈是 0.4.0 主目标之一。为了让真实学员闭环更顺，建议同版本纳入：

- 补论坛作业分享 / 提问模板，让“操作卡住”的学员知道该怎么把问题发清楚。
- 管理员后台补一个“最需要处理的课程”视图：优先列出 `blocked` 比例高、`confusing` 比例高、最近反馈多的课程。

暂不纳入：

- 完整学习进度系统。
- 作业打分。
- 评论精选。
- 即时逐条通知。
- 管理员手动触发每日摘要群发入口。
- 反馈状态历史表。

## 13. 验收标准

- 未解锁用户无法提交反馈，也不能看到反馈统计或讨论回复。
- 已注册但未解锁课程 / 论坛的用户，也不显示课程反馈区。
- 已解锁用户不选状态不能提交。
- 已解锁用户文字为空不能提交。
- 同一用户同一课程重复提交只更新一条反馈。
- 后台统计三种状态计数正确。
- 用户修改反馈后，后台统计从旧状态移到新状态，不保留旧状态计数。
- 反馈文字能在课程讨论帖中出现。
- 论坛页编辑课程反馈回复时，只能改文字，状态保持不变并继续由 `course_feedback.status` 生成状态标签。
- 论坛同步失败时，反馈仍保存成功，后台能看到未同步状态。
- 课程反馈同步出的论坛回复被隐藏 / 删除后，对应反馈从课程页汇总和后台状态统计中移除。
- 已撤回反馈再次提交时恢复同一条反馈记录并创建新的论坛回复，统计重新计入。
- 用户可在课程页撤回自己的反馈，撤回后课程页不再显示为已提交，统计移除。
- 更新反馈时不会无限新增论坛回复。
- MCP 反馈工具与网页反馈保持同语义。
- `pnpm typecheck` 和 `pnpm build` 通过。

## 14. MCP 验收 Checklist

用 owner/admin 和一个普通学员账号分别验收；不要在聊天、Issue 或日志里粘贴课程正文、token、卡密或私密反馈全文。

- `auth_whoami`：确认 MCP token 属于目标学员。
- `course_list_metadata`：选择一节已发布课程 slug。
- `course_feedback_get_summary`：未提交前能读取汇总；未解锁账号不能读取。
- `course_feedback_dry_run_submit`：用 `✅ 顺利` / `🤔 内容难懂` / `🐛 操作卡住` 各测一次校验；确认 dry run 提示真实提交会公开同步课程讨论帖。
- `course_feedback_submit`：提交一条非空 Markdown 反馈，确认返回 `discussionLinked`。
- `course_feedback_get_summary`：确认当前用户反馈和状态统计变化。
- `forum_read_post`：读取对应课程讨论帖，确认反馈同步为论坛回复，正文第一行带状态标签。
- `course_feedback_submit`：更新状态和文字，确认仍是同一条反馈，论坛回复被整体重写而不是新增楼层。
- `course_feedback_withdraw`：撤回反馈，确认统计移除，课程讨论帖对应回复被隐藏 / 删除。
- `course_feedback_submit`：撤回后再次提交，确认恢复同一条反馈记录并创建新的论坛回复。
- 未登录 / 未解锁用户通过页面验收：课程底部不显示反馈区。
